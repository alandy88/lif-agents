# backlog

## Overview

Turn recent planning docs in `lif-notes/system/plans/` into properly-sized Linear
backlog cards, each routed to the correct execution lane. This skill is the
**producer** — it creates and initially routes cards via the Linear MCP. `swarm-pi`
is the consumer that watches the `Agent Ready` state (lif-studio ADR-0013).

## Hard rules

- Never CREATE or move a Linear card without explicit maintainer confirmation in the
  same turn. Scanning, sizing, and recommending are non-destructive and need no gate.
- Each card must be sized to finish within ~100k tokens of context. Oversized docs are
  split before any card is created. See `references/sizing.md`.
- Every triage comment posted to Linear MUST start with:
  `> *This was generated by AI during triage.*`

## Prerequisite check

Confirm `$LIF_NOTES_VAULT/docs/agents/issue-tracker.md` and `$LIF_NOTES_VAULT/docs/agents/triage-labels.md` exist (the
seam the authoring skills read). If either is missing, tell the maintainer and offer
to create them from the lif-studio originals before continuing — do not guess the
mapping.

## Checklist

Create a TodoWrite task per step and complete in order:

1. **Scan** recent docs
2. **Select** which to promote
3. **Size** each pick (T-shirt + 100k budget), propose splits
4. **Author** the card(s) on Linear
5. **Route** each card to its lane via triage

## Step 1 — Scan

Glob `$LIF_NOTES_VAULT/system/plans/*.md`. Parse the leading `YYYY-MM-DD` from each filename;
keep those within N days of today (default 7; `--days N` overrides). Ignore files
without a date prefix.

For each kept doc, read the first ~40 lines to classify type
(design / PRD / runbook / report / migration) and extract a one-line summary.

Present a table, newest first: `date · file · type · summary · recommend?`.
Recommend promoting implementable design/PRD docs; do NOT recommend already-executed
runbooks or after-the-fact reports (note them, but mark "skip — already done/retrospective").

## Step 2 — Select

If the maintainer passed `doc-name` arguments, use those. Otherwise ask which to
promote (1 or more). Wait for the choice.

## Step 3 — Size

For each picked doc, read it in full and apply the rubric in `references/sizing.md`:
assign S / M / L / XL and an estimated implementation-context token cost. The rule:
**each resulting ticket must fit within ~100k tokens.** For XL docs, propose a split
into child tickets using `to-issues` vertical-slice logic, each sized to fit.

Present sizing + any proposed split as a numbered list and get approval before creating
anything.

## Step 4 — Author cards

For each approved unit, invoke the authoring skill that fits and let it publish through
the lif-notes seam (`Skill` tool):

- A single tracking card → `to-prd` (synthesize the body), then create the card.
- A split into slices → `to-issues` (it produces the slices and publishes them).

Cards are created via `mcp__plugin_linear_linear__save_issue` with `team: "LIF Studio"`,
`state: "Backlog"`, labels `lif-notes` + one category (`Feature`/`Improvement`/`Bug`).
Echo each created card's identifier and URL.

## Step 5 — Route to lane

Run a `triage` readiness pass (`Skill` tool) per created card. Map the verdict to a
Linear state/label per `references/lane-routing.md`:

- **AFK-ready** → set state `Agent Ready` (swarm-pi will pick it up).
- **Human-only** → `ready-for-human` label, stays in `Backlog`.
- **Gaps** → `needs-info` label, stays in `Backlog`.
- **Exploratory** → `spike` label, stays in `Backlog`.

Post a readiness checklist (what is specified vs. missing) as a Linear comment with the
AI-triage disclaimer, then summarize the verdicts and lane assignments to the maintainer.

## Reference map

- `references/sizing.md` — T-shirt sizes and the ~100k-token budget rule
- `references/lane-routing.md` — triage verdict → Linear state/label table

## Key principles

- **Producer, not executor** — this skill creates and routes; it never implements the work.
- **Confirm before writing** — scanning/sizing is free; card creation and lane moves are gated.
- **100k budget is the splitting law** — size drives whether a doc is one card or many.
- **Reuse the authoring skills** — bodies come from `to-prd`/`to-issues`, not a bespoke template.
