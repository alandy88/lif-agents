# Lane routing — triage verdict → Linear state/label

Mirrors lif-studio ADR-0013 and `lif-notes/docs/agents/triage-labels.md`. The board
states are `Backlog → Agent Ready → In Progress → Blocked → In Review → Done` (+ `Canceled`).
Only `Agent Ready` is machine-watched — moving a card there is the sole AFK trigger.

| Verdict (from `triage`)                         | Lane            | Linear action                         | Kind  |
| ----------------------------------------------- | --------------- | ------------------------------------- | ----- |
| Fully specified, self-contained, ≤ ~100k        | AFK (swarm-pi)  | set state `Agent Ready`               | state |
| Needs human judgment / design / manual access   | HITL (Claude Code) | `ready-for-human` label, stay `Backlog` | label |
| Material gaps / questions for reporter          | (held)          | `needs-info` label, stay `Backlog`    | label |
| Exploratory idea, not ready to build            | (held)          | `spike` label, stay `Backlog`         | label |
| Will not be actioned                            | —               | set state `Canceled`                  | state |

## How to apply

- **State** (`Agent Ready`, `Canceled`): `mcp__plugin_linear_linear__save_issue` with the
  target `state`.
- **Label** (`ready-for-human`, `needs-info`, `spike`): `save_issue` with the label added.

## Disclaimer

Every triage comment posted to Linear MUST begin with:

    > *This was generated by AI during triage.*

## Decision guidance

- Prefer **AFK** when the card is unambiguous, the acceptance criteria are testable, and
  no design decision or external/manual access is required.
- Choose **HITL** when the work needs a judgment call, a design choice, manual verification,
  or access the agent lacks.
- A card that is AFK-ready in scope but over ~100k tokens is NOT AFK-ready — it must have
  been split in Step 3 first.
