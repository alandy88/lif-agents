# backlog

Turn recent plans in `$LIF_NOTES_VAULT/system/plans/` into GitHub issues, each sized to
fit one agent session and routed with a triage label. This skill creates and labels
issues; it never implements them.

The vault's tracker contract is the source of truth. Read both files before step 4; if
either is missing, tell the user and stop rather than guess the mapping:

- `$LIF_NOTES_VAULT/docs/agents/issue-tracker.md`: which repository an issue goes to and
  what its body carries.
- `$LIF_NOTES_VAULT/docs/agents/triage-labels.md`: the triage labels and their meaning.

## Rules

- Create, label or close nothing without the user's yes in the same turn. Scanning,
  sizing and recommending need no gate.
- Each issue fits in about 100k tokens of context. Split bigger work before creating
  anything; see [references/sizing.md](references/sizing.md).
- Every triage comment starts with `> *This was generated by AI during triage.*`
- Never publish red-tier vault content.

## Steps

Create a TodoWrite task per step and work them in order.

1. **Scan.** List the plans with Bash (Glob cannot reach the vault from another repo):

   ```bash
   ls -1 "$LIF_NOTES_VAULT/system/plans/"*.md
   ```

   Keep files whose leading `YYYY-MM-DD` is within N days of today (default 7;
   `--days N` overrides); skip files without a date prefix. Read the first ~40 lines of
   each to classify it (design, PRD, runbook, report, migration) and summarise it in one
   line. Show a table, newest first: `date · file · type · summary · recommend?`.
   Recommend implementable designs and PRDs; mark executed runbooks and reports
   "skip: already done".
2. **Select.** Use the `doc-name` arguments if given; otherwise ask which docs to
   promote and wait.
3. **Size.** Read each pick in full and size it with
   [references/sizing.md](references/sizing.md). Split XL work into vertical slices.
   Show a numbered list (size, estimate, owning repository, blocking order) and wait
   for approval.
4. **Create.** For each approved unit, search the owning repository first and create an
   issue only when none fits:

   ```bash
   gh issue list --repo <owner/repo> --state all --search "<keywords>"
   gh issue create --repo <owner/repo> --title "<title>" --body-file <file> --label <category>
   ```

   Drop `--label` when the repository has no category label (`bug`, `enhancement`). The
   body stands alone and carries `Source: lif-notes <plan path>`. Create split slices
   in blocking order and write `Blocked by #<n>` in each dependent body. Echo each URL.
   If the user wants `to-spec` to write a body or `to-tickets` to make the split, those
   skills are user-only: ask the user to run `/mattpocock-skills:to-spec` or
   `/mattpocock-skills:to-tickets` for that unit instead.
5. **Route.** Pick each issue's verdict with
   [references/lane-routing.md](references/lane-routing.md), apply its label with
   `gh issue edit <n> --repo <owner/repo> --add-label <label>`, and post the readiness
   checklist (what is specified, what is missing) with `gh issue comment`, starting with
   the disclaimer. Summarise the verdicts to the user.

## Done when

Every approved unit is an issue (new or found), each carries one triage label or is
closed as not planned, and each has a readiness comment.
