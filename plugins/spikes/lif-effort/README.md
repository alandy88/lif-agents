# lif-effort compatibility spike — issue #55

**Gate: no-go on Claude Code 2.1.295.** This directory is an unshipped experiment,
not the proposed `lif-effort` plugin. It is not registered in the marketplace or
installed in the user's configuration. The required core controls are blocked;
per the issue, implementation stops here rather than substituting slash commands
or quietly changing the UI design.

## What the installed engine actually supports

| Requirement / probe | Evidence on 2.1.295 | Result |
| --- | --- | --- |
| `PromptActions.topRow` buttons | Native validator: `no component is named PromptActions, so it never runs`. The declarations generated by this installed engine also reject the matcher. | **Blocked** |
| Read the native model | `$.session.model()` returned `claude-opus-5-5`. | Supported |
| Read the native effort before a request | `$.config.list()` returned no effort row. The generated mods API has no session effort getter. `turn.step` exposes the effort only when a request happens. | No documented pre-request getter |
| Change native model without persistent settings | `$.config.set({ key: 'model', value: 'sonnet' })` changed the session model to `claude-sonnet-5-5` **and wrote** `{"model":"sonnet"}` to the isolated config directory's `settings.json`. | Fails the no-global-model-config design |
| Native session-only model / effort setters | Not exposed by this engine's generated mods API. Running builtin `/model` or `/effort` is not the required API-based control. | Not established |
| Rewrite an API request's model / effort | Native event tests passed `next({ ...e, model: 'claude-sonnet-5-5', effort: 'low' })` for main requests, leaving subagents untouched. | Supported alternative, not native control state |
| Small-model call | A real headless `$.model.complete` on `haiku`, 8-token cap, 1500 ms timeout, returned `SIMPLE`. | Supported |
| Failure / timeout / invalid classifier response | Native tests returned a deterministic local `COMPLEX` fallback. | Supported |
| Drawing a clickable button elsewhere | `AbovePrompt` preserved native content; mounted button tests passed on terminal and desktop. A real interactive terminal painted `Read session model`. | Supported alternative, **not** `topRow` |

The routing experiment is deliberately pinned to the Sonnet ID observed on this
build; it is not a production model-support matrix. Request rewriting does not
change the native session model, model picker, or effort indicator. No live
conversation was routed through it: its boundary was tested with the engine's
network-free event runner. The desktop drawing was tested in that runner, not in
the desktop app.

## Evidence and checks

The exact blocking warning from `claude plugin validate` is:

```text
on ui.render{component=PromptActions}: no component is named PromptActions, so it never runs
```

The model-write experiment, in a temporary `CLAUDE_CONFIG_DIR`, returned:

```json
{
  "before": "claude-opus-5-5",
  "result": { "value": "sonnet" },
  "after": "claude-sonnet-5-5"
}
```

That temporary directory then contained `settings.json` with `model: "sonnet"`.
The user's settings were not the write target. Temporary credentials and session
artifacts used by the live probes were removed afterwards.

Checks completed:

- `claude plugin test plugins/spikes/lif-effort`: 9 passing tests, no network.
- `claude plugin validate plugins/spikes/lif-effort`: passes with the **intentional
  blocking warning** above; a zero exit status does not make this a compatible UI.
- `bunx tsc -p plugins/spikes/lif-effort --noEmit`: passes against declarations
  generated by **2.1.295**, including an expected type error for `PromptActions`.
- `bun run typecheck` and `bun run test`: pass, 260 existing tests.
- Real interactive terminal: supported `AbovePrompt` probe painted successfully.
  This is not a successful smoke test of the issue's required control row.

## Repeat the probe

From the repository root:

```sh
claude --version
claude plugin validate plugins/spikes/lif-effort
claude plugin test plugins/spikes/lif-effort
# Session-local loading only; do not install the experiment:
claude --plugin-dir ./plugins/spikes/lif-effort
```

The interactive load generates ignored `.claude-plugin/types/` declarations for
that engine. Afterwards, run the standalone typecheck command above. The
`@ts-expect-error` on the negative `PromptActions` probe will become an unused
expectation if a future engine exposes that site: re-evaluate the gate then.

The probe registers `/lif-effort-spike` with these explicit actions:

- `report` (default): print engine version, model, model row, and any effort rows.
- `classify`: make the tiny greeting-only model call; invalid or failed results
  use the local fallback. It sends no conversation history.
- `route` / `unroute`: enable / disable the **experimental request-only** override
  for subsequent main requests. Off by default; nothing is saved.
- `write-model`: deliberately exercise the persistent model writer. Refused
  unless both `CLAUDE_CONFIG_DIR` and `LIF_EFFORT_SPIKE_ALLOW_SETTINGS_WRITE=1` are
  set. **Only run in a fresh temporary config directory**, never in the normal
  user configuration; delete that directory afterwards. Neither this action nor
  `classify` runs automatically on startup or render.

## Decision needed before implementation

Either identify a supported Claude Code build/API that provides the required
native row and runtime controls, or explicitly revise #55 to accept a supported
render site plus request-only model/effort routing. That revised design must also
explain the difference between native control values and effective request values.
The full plugin, its automation state machine, session tools, and optional panels
remain unimplemented. The production plugin's location/name and minimum version
are therefore not finalized.
